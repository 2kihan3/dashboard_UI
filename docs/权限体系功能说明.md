# 权限体系功能说明

## 1. 权限模型

系统采用“组织权限 + 业务权限 + 资源权限”的组合方式。

```text
平台账号
├─ 组织关系：是否为系统管理员、所属商户团队、所属小组
├─ 组织角色：商户管理员 / 小组长 / 普通成员
└─ 业务角色：决定生产端可执行的功能、页面、按钮和数据操作

资源目录
└─ 模块 → 功能 → 页面 → 按钮

最终生效权限
└─ 组织范围 ∩ 团队或小组已开通模块 ∩ 业务角色资源权限
```

- 组织权限解决“谁能管理什么范围”的问题，主要作用于 Manager 管理端。
- 业务权限解决“账号在生产端能做什么”的问题，配置到模块、功能、页面、按钮及数据操作。
- 团队和小组的模块开通范围是上限。即使业务角色包含某项能力，团队或小组未开通对应模块时，商户侧也不能授予或使用该能力。

## 2. 功能权限

功能权限用于维护整个平台可被授权的资源目录，是角色配置、菜单展示和接口校验的基础。

### 2.1 资源层级

| 层级 | 说明 | 子级维护方式 |
|---|---|---|
| 模块 | 平台中的独立业务域，例如商智引擎、电商生图 | 模块下新增功能 |
| 功能 | 模块中的能力入口；可作为直接路由页面，也可作为展开容器 | 功能下新增页面；若为直接页面，可继续新增按钮 |
| 页面 | 具体的业务页面或子页面 | 页面下新增按钮 |
| 按钮 | 页面内的操作权限点，例如发布、修改、下载源表 | 无下级 |

功能节点支持两种形态：

- 页面型功能：自身配置页面路由，可直接进入页面，也可以在下方继续配置按钮。
- 容器型功能：自身不作为实际页面入口，点击后仅展开或收起下级页面。

四级树和三级树可以在同一资源目录中混合存在。授权时只保存可执行或可访问的末级权限点；勾选父级时，系统将父级下的末级权限点批量加入或移除，因此不影响前端菜单渲染和后端权限校验。

### 2.2 通用字段

模块、功能、页面、按钮均配置以下字段：

| 字段 | 用途 |
|---|---|
| 名称 | 前端展示名称 |
| 标识 | 稳定的资源编码，用于权限点、菜单和接口关联 |
| 排序 | 同级资源的展示顺序 |
| 状态 | 启用或停用；停用资源不参与正常授权和展示 |

模块、功能、页面额外配置“页面路由”。按钮不配置页面路由，可额外维护说明、操作类型、权限点标识、关联接口和请求方法，便于审计和接口校验。

### 2.3 配置操作

- 模块：新增、编辑模块；在模块下新增功能。
- 功能：新增、编辑功能；创建时选择“页面”或“按钮”类型。页面型功能显示页面路由，按钮型功能不显示页面路由。
- 页面：新增、编辑页面；在页面下新增按钮。
- 按钮：新增、编辑按钮；用于定义具体操作权限。
- 功能权限页以一棵连续父子树展示全部资源，不按模块拆成多个独立卡片。

## 3. 角色管理

角色管理分为“组织角色”和“业务角色”两个 Tab。

### 3.1 组织角色

组织角色用于控制 Manager 管理端的管理能力和管理范围。

| 角色 | 默认定位 | 权限配置规则 |
|---|---|---|
| 商户管理员 | 管理商户团队、成员、小组及商户范围内配置 | 默认拥有 Manager 端全部权限，可在系统级模板中编辑 |
| 小组长 | 进入 Manager 端并管理所属小组 | 默认不配置具体后台能力，可按需开放 Manager 端权限 |
| 普通成员 | 组织身份占位 | 不参与 Manager 端权限分配，权限编辑按钮禁用 |

组织角色权限以连续树展示 Manager 端的模块、页面和操作项。勾选父级会批量勾选所有下级权限点；部分勾选时父级显示半选状态。

当前组织权限目录包含：

```text
数据概览
团队管理
├─ 成员管理：新增、删除、编辑、查看、禁用、豌豆分配
├─ 小组管理：小组增删改查、豌豆分配
├─ 小组成员：增删改查、豌豆分配
├─ 平台管理：平台增删改查、店铺绑定
├─ 权限管理：组织权限、业务权限
└─ 操作日志
任务管理
├─ 电商生图：豌豆值消耗记录
└─ 商智引擎
资源管理
├─ 电商生图：灵感中心、Coze 模版套装、提示词模版、姿势库预设、Logo 管理
└─ 商智引擎
```

### 3.2 业务角色

业务角色用于配置生产端的功能和数据操作权限。系统预设角色支持新增、编辑、启用、停用和删除；删除前必须先停用。

角色列表字段：

| 字段 | 说明 |
|---|---|
| 角色名称 | 例如运营专员、数据分析师 |
| 可用团队 | 可使用该系统级角色的商户团队范围 |
| 成员数量 | 当前绑定该角色的成员数 |
| 状态 | 启用或停用 |
| 操作 | 编辑、启停、删除 |

系统级角色编辑时，“可用团队”通过独立多选弹窗选择：弹窗展示完整团队列表，支持纵向滚动、全选、清空和确认回写。

商户管理员在 Manager 端配置本团队业务角色时，范围字段改为“可用小组”，仅展示当前商户团队下的小组及其已开通模块。商户侧业务角色不能越过小组模块开通范围。

当前生产端业务权限树示例：

```text
商智引擎
├─ chatbot
├─ 经营看板
│  ├─ 全局看板
│  ├─ 团队看板
│  └─ 个人看板
├─ 数据中心
│  ├─ 日报任务记录
│  │  ├─ 发布
│  │  ├─ 修改
│  │  ├─ 重试
│  │  ├─ 人工上传
│  │  └─ 下载源表
│  └─ 日报数据
│     └─ 手动填写
├─ skill市场
└─ 数据溯源

电商生图
```

## 4. 用户管理

用户管理是平台级全局账号池，仅由超管和系统管理员使用。商户管理员不拥有平台用户管理权限。

### 4.1 用户列表

列表展示成员、用户类型、手机号、公司、部门、岗位、员工编号、加入团队数、账号状态、注册时间、最后登录时间和操作入口。

支持以下账号操作：

- 编辑基础信息。
- 启用或停用账号。
- 删除账号。

### 4.2 新增用户

新增弹窗提供“超管”和“系统管理员”两个创建入口，通用字段为：用户名、昵称、邮箱、员工编号、联系电话、初始密码。

| 创建人 | 可配置内容 |
|---|---|
| 超管 | 可选择是否设为系统管理员；可选择是否归属商户团队 |
| 系统管理员 | 不可创建系统管理员；可选择是否归属商户团队 |

归属商户团队选择“是”后，级联显示：

1. 商户团队选择。
2. 团队组织角色：商户管理员或普通成员。

归属商户团队选择“否”时，只创建全局账号，不强制绑定团队。后续可由商户管理员通过团队管理邀请该账号加入团队。

## 5. 团队管理

团队管理位于商户管理员的 Manager 端，用于维护当前商户团队内的成员、小组、业务角色、平台和其他团队资产。

### 5.1 商户管理员能力

商户管理员可查看并管理当前团队全部成员，并可执行：

- 创建成员。
- 邀请已有全局账号。
- 编辑成员基础信息。
- 分配或调整商户管理员身份、小组归属、小组角色和业务角色。
- 启停成员、删除成员、分配或回收豌豆。
- 管理小组、平台、仪表盘、团队权限和操作日志。

创建成员时：

1. 填写完整账号信息。
2. 必须选择业务角色。
3. 可选择是否分配商户管理员身份。
4. 可选择是否分配小组。选择后配置小组名称和“小组长 / 组员”。
5. 若团队没有小组，页面提示“当前商户团队中没有小组，请到小组管理中进行创建”。

邀请已有用户时：

1. 仅允许输入完整邮箱地址进行精确匹配，不提供模糊搜索。
2. 匹配到全局账号后，必须选择业务角色。
3. 商户管理员可选择普通成员或商户管理员组织身份。
4. 同一账号已在当前团队时，不重复创建成员记录，而是更新业务角色和组织身份。

### 5.2 小组与模块范围

创建小组时需配置小组名称、组长、小组可见模块和关联店铺。

- 小组可见模块由小组统一控制，是成员生产端可见范围的上限。
- 成员不能单独增加小组未开通的模块。
- 业务角色中的权限只在小组已开通模块内生效。

### 5.3 小组长能力边界

小组长的范围固定为所属小组：

- 只能查看所属小组成员。
- 可创建成员，创建后强制绑定当前小组，并固定为组员。
- 可用完整邮箱邀请团队内已有账号或全局账号；邀请后强制加入当前小组，并固定为组员。
- 创建和邀请均必须选择业务角色。
- 不可额外分配商户管理员身份，不可跨小组查看或维护成员。

## 6. 权限生效与校验顺序

账号访问某个生产端资源时，按以下顺序判断：

1. 账号状态必须正常。
2. 账号必须具有有效的团队或小组组织关系；无团队归属的全局账号不直接获得商户生产权限。
3. 团队或小组必须开通目标模块。
4. 账号绑定的业务角色必须包含目标功能、页面或按钮权限。
5. 涉及数据范围时，还需要按团队、小组、平台、店铺和字段范围继续过滤。

因此，业务角色权限大于团队或小组开通范围时，最终以团队或小组范围为准：未开通模块不展示、不允许分配，也不允许实际访问。
