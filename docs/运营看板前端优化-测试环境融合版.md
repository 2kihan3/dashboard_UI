# 运营看板前端优化：测试环境融合版

## 范围

只修改 dashboard-UI 的运营看板。财务看板及 UI 全栈项目不变，无接口接入、数据库写入或测试环境修改。

## 信息结构

- 单页顺序固定为：顶部经营概况 → 商品数据波动（新增、下滑）→ 曝光点击率与点击成交率 → 商品贡献与投放 → 商品明细 → 团队归因。不提供内部二级 Tab。
- 商品 / 原始货号切换，人员、小组与关键词筛选；按支付金额或订单数（估算）降序排列商品和波动列表。
- 小组 / 个人只切换归因指标，不切换页面。
- 新增和下滑默认各展示 5 条，可调整为 10 条；查看更多弹窗展示最多 TOP100，支持 10 / 20 / 50 条每页、页码、上一页与下一页。
- 商品、流量与团队排行榜改为紧凑排名列表，不再使用横向条形图。左侧名称和归属 / 人数样本，右侧精确数值；前三名轻量标识。每个榜默认展示前 5 条，查看更多打开每页 5 条的分页弹窗，仍仅展示已读取样本。

主界面采用两列卡片，窄屏一列；样本筛选吸顶。图表可选择商品，对应数据在明细面板显示；键盘用户可使用表格查看按钮。原有诊断演示组件保留源文件，但不再作为本页面入口。

## 数据边界

`src/data/operationsSnapshot.ts` 记录 2026-09-17 从测试环境运营面板读取的可见值，不是完整导出或实时连接。

- 全店铺指标原样保留，不受商品排行样本筛选影响。
- 商品支付排行十条，流量排行各六条可见样例，小组和个人排行各十条。
- 商品名称为简称，ID、货号和数值保留读取值。
- 商品推广图只使用支付排行中已匹配推广金额的样本，不冒充全量推广榜。
- 跨店铺商品身份和标准款号映射未经确认；样本未提取店铺归属，因此不提供虚假店铺筛选。
- 无货号商品按独立 ID 保留；不擅自剥离货号后缀。
- 点击率和成交率采用人数口径。估算商品订单不用于计算人数转化率。
- 退款按支付时间金额口径，不等同成熟批次件数退货率。
- 全店铺汇总、商品排行和团队排行分母未确认一致，不混算贡献率。
- 一人多组可能重复归因，不提供占比饼图。
- 每日趋势数值、同商品完整曝光 / 点击 / 成交关联未提取，因此展示缺失状态，不伪造曲线或气泡。
- 原页面商品波动为“无显著波动”。为验收新增 / 下滑 TOP100 交互，提供各 100 条独立虚拟样本并明确标注，不参与任何真实汇总。
- 新增演示定义为前日无成交而当日有成交，下滑定义为当日支付金额低于前日；正式阈值待业务确认。

## 后续数据接入

接入完整日明细后补充店铺筛选、时间查询、完整商品排行、货号规范化、支付与推广独立趋势、联合转化气泡、真实双向波动。保持未采集与零值区别。
